# Manage Dependencies

Detect the project's Python package manager and generate project-specific enforcement rules and guidance.

## Dual-write (Cursor + Claude Code)

Never `ln -s`. Always write real files to both tools.

**Rule `<name>`:** write `.cursor/rules/<name>.mdc` (keep `alwaysApply` / `globs`) and `.claude/rules/<name>.md` (drop `alwaysApply`; convert `globs` to `paths:` as a YAML list; same markdown body).

**Skill `<name>`:** write or `cp -R` to both `.cursor/skills/<name>/` and `.claude/skills/<name>/`.

## Phase 1: Detect Package Manager

### 1.1 Inspect project files

Check the project root for these files, in priority order:

1. **uv.lock** exists → **uv**
2. **pyproject.toml** contains `[tool.uv]` → **uv**
3. **poetry.lock** exists → **Poetry**
4. **pyproject.toml** contains `[tool.poetry]` → **Poetry**
5. **requirements.txt** exists (and none of the above matched) → **pip**
6. Nothing found → ask the user which manager they use

### 1.2 Detect private registry

Check for CodeArtifact or other private registry configuration:

- **pyproject.toml**: look for `[[tool.poetry.source]]` or `[tool.uv.index]` entries with non-PyPI URLs
- **.envrc** or **.env**: look for `UV_EXTRA_INDEX_URL` or `PIP_EXTRA_INDEX_URL`
- **pip.conf** (if pip): look for `index-url` or `extra-index-url` pointing to non-PyPI hosts

Set `has_private_registry = true` if any are found.

### 1.3 Confirm with user

Use `AskQuestion`:

```yaml
title: "Dependency Manager Detection"
questions:
  - id: confirm
    prompt: "Detected **<detected_manager>** as the dependency manager<private_registry_note>. Is this correct?"
    options:
      - id: "yes"
        label: "Yes, that's correct"
      - id: uv
        label: "No, this project uses uv"
      - id: poetry
        label: "No, this project uses Poetry"
      - id: pip
        label: "No, this project uses pip with requirements.txt"
```

Where `<private_registry_note>` is ` (with private registry)` if detected, or empty string otherwise.

If the user corrects the detection, use their answer instead.

## Phase 2: Generate Artifacts

Based on the confirmed manager, generate two files:

### 2.1 Enforcement rule

Read the matching template from this skill's `templates/` directory:

- **uv** → read [templates/uv-rule.md](templates/uv-rule.md)
- **Poetry** → read [templates/poetry-rule.md](templates/poetry-rule.md)
- **pip** → read [templates/pip-rule.md](templates/pip-rule.md)

Dual-write the template contents as `dependency-management` (`.cursor/rules/dependency-management.mdc` and `.claude/rules/dependency-management.md`).

If `has_private_registry` is true, append the private registry note from the template (each template has a `<!-- PRIVATE REGISTRY -->` section at the end — keep it if private registry detected, remove it otherwise).

### 2.2 Guidance skill

Read the matching template:

- **uv** → read [templates/uv-skill.md](templates/uv-skill.md)
- **Poetry** → read [templates/poetry-skill.md](templates/poetry-skill.md)
- **pip** → read [templates/pip-skill.md](templates/pip-skill.md)

Create both `.cursor/skills/manage-dependencies/` and `.claude/skills/manage-dependencies/` and write the template contents to `SKILL.md` in each. Never `ln -s`.

If `has_private_registry` is true, keep the `<!-- PRIVATE REGISTRY -->` section. If false, remove it.

## Phase 3: Confirm

Tell the user:

- The dependency management rule has been dual-written to `.cursor/rules/dependency-management.mdc` and `.claude/rules/dependency-management.md` (always active — enforces correct package manager in every chat)
- The dependency management skill has been dual-copied to `.cursor/skills/manage-dependencies/SKILL.md` and `.claude/skills/manage-dependencies/SKILL.md` (detailed reference for dependency operations)
- Which package manager was detected/confirmed
- Whether private registry integration was included
- Suggest running the `codeartifact-auth` skill if they need to set up private registry authentication
