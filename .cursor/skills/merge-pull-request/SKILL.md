# Merge a Pull Request

Merge an approved GitHub pull request, delete the head branch, and check out the PR's base branch.

Do **not** use this skill for a bare "checkout to main" with no merge intent. Do **not** use `git-merge` (that skill is local merge/rebase/cherry-pick).

## Core Workflow

1. Detect GitHub access (MCP preferred, `gh` fallback) and resolve `owner/repo`
2. Identify the PR (URL/number, current-branch PR, or ask)
3. Safety checks — open, not draft, no conflicts; warn if GitHub does not show APPROVED
4. Choose merge strategy (explicit squash / merge commit / rebase only; else AskQuestion)
5. Merge, delete remote + local head, check out **the PR's base**, `git pull`
6. Summarize URL, method, deleted branch, current branch

---

## GitHub API Access

Before performing any GitHub operations, determine which access method is available:

1. **GitHub MCP** (preferred): Check if a GitHub MCP server is configured by scanning the mcps folder for a server matching `github` or containing `github` in its name. If found, verify with a `get_me` call. Note the server name for all subsequent MCP calls.
2. **gh CLI** (fallback): Run `gh auth status` to verify authentication.

Also resolve `owner` and `repo` from the git remote:

```bash
git remote get-url origin
```

Parse `owner/repo` from the URL. Store these values — GitHub MCP tools require them as explicit parameters on every call.

Use the detected method consistently for all operations below. Each operation shows both methods: **MCP** first, then **CLI**.

---

## Constraints

### MUST DO
- Check out the PR base (`base.ref` / `baseRefName`). Never hardcode `main`.
- Delete the remote head after a successful merge. MCP `merge_pull_request` does **not** delete the branch — delete `refs/heads/<head>` afterward. `gh pr merge --delete-branch` already does this.
- Delete the local head after switching off it. Do not leave the user on the deleted branch.
- Confirm merge strategy unless the user already named squash, merge commit, or rebase. A lone "merge" / "merge the PR" is not a named strategy.

### MUST NOT DO
- Merge a draft or an already-merged PR
- Force-push or hard-reset
- Trigger on a bare "checkout to main" / "checkout to staging" with no merge intent
- Confuse this skill with `git-merge` (local integrate/rebase/cherry-pick)

## Phase 1: Identify the PR

Record the current branch:

```bash
git branch --show-current
```

### 1.1 Resolve which PR

Use this priority:

1. The user gave a PR URL — parse `owner`, `repo`, and number from `https://github.com/<owner>/<repo>/pull/<n>` (also `/pulls/<n>`). Compare that `owner/repo` to origin. If they differ, **stop**: "That PR is in `<url-owner>/<url-repo>`, but this clone is `<origin-owner>/<origin-repo>`." Do not merge using origin. If they match, use the parsed number.
2. The user gave only a number — use it with origin `owner/repo`.
3. Else look up the PR for the current branch.
4. Else list open PRs and AskQuestion.

**Current-branch lookup — via MCP:**

```
CallMcpTool: server=github, toolName=list_pull_requests
arguments: { "owner": "<owner>", "repo": "<repo>", "state": "open", "head": "<owner>:<current-branch>", "fields": ["number", "title", "html_url", "head", "base", "draft", "state"] }
```

**Current-branch lookup — via CLI:**

```bash
gh pr view --json number,url,title,state,isDraft,mergeable,mergeStateStatus,reviewDecision,baseRefName,headRefName
```

**List open PRs — via MCP:**

```
CallMcpTool: server=github, toolName=list_pull_requests
arguments: { "owner": "<owner>", "repo": "<repo>", "state": "open", "fields": ["number", "title", "html_url", "head", "base", "draft"] }
```

**List open PRs — via CLI:**

```bash
gh pr list --state open --json number,title,url,headRefName,baseRefName
```

If none exist, stop and tell the user there is no open PR to merge.

### 1.2 Load full details

Store: number, url, title, state, draft, mergeable, mergeStateStatus / `mergeable_state`, reviewDecision, `base.ref`, `head.ref`.

**Via MCP:**

```
CallMcpTool: server=github, toolName=pull_request_read
arguments: { "owner": "<owner>", "repo": "<repo>", "pullNumber": <number>, "method": "get" }
```

```
CallMcpTool: server=github, toolName=pull_request_read
arguments: { "owner": "<owner>", "repo": "<repo>", "pullNumber": <number>, "method": "get_reviews" }
```

MCP has no `reviewDecision` field. Treat as APPROVED only when the latest review from at least one reviewer is `APPROVED` and no reviewer's latest review is `CHANGES_REQUESTED`. Otherwise treat as not APPROVED.

**Via CLI:**

```bash
gh pr view <number> --json number,url,title,state,isDraft,mergeable,mergeStateStatus,reviewDecision,baseRefName,headRefName
```

## Phase 2: Safety checks

Run in this order. Stop at the first hard failure.

**Already merged or closed:**
- Stop. Offer local cleanup only (Phase 5) if the user is still on the head branch.

**Draft:**
- Stop: "This PR is still a draft. Mark it ready for review before merging."

**Conflicts (hard stop only):**
- CLI: `mergeable` is `CONFLICTING`, or `mergeStateStatus` is `DIRTY`. (`gh pr view --json mergeable` returns `MERGEABLE` / `CONFLICTING` / `UNKNOWN`, not a boolean. `false` is not a CLI value.)
- MCP: `mergeable` is `false`, or `mergeable_state` is `dirty`.
- Stop and report the GitHub reason. Do not merge.

**BLOCKED:**
- `mergeable_state` / `mergeStateStatus` is `BLOCKED` (typical when required reviews are missing). Do **not** hard-stop. Continue to the reviewDecision AskQuestion — that is the admin-merge path.

**UNSTABLE:**
- `UNSTABLE` means mergeable with non-required checks failing. Do **not** hard-stop.

**UNKNOWN:**
- Not a conflict. Continue the remaining checks; GitHub will reject the merge if it cannot proceed.

**reviewDecision is not APPROVED:**
- Warn and AskQuestion:

```
prompt: "GitHub does not show this PR as approved (reviewDecision=<value>). Merge anyway?"
options:
  - Merge anyway
  - Abort
```

The user already said the PR is approved — do not silently block an admin merge.

**Dirty working tree that would block checkout:**

```bash
git status --porcelain
```

If there are uncommitted changes, AskQuestion:

```
prompt: "Uncommitted changes would block switching to <base>. What should we do?"
options:
  - Stash, then continue
  - Abort
```

If stash: `git stash push -u -m "merge-pull-request: WIP from <head> before checkout <base>"`.

The skill always ends on `<base>`. Do **not** `git stash pop` there — that applies feature WIP onto `main` / `staging` / the parent.

Tell the user:
- The stash came from `<head>`
- They are now on `<base>`
- To recover WIP: create a new working branch, then `git stash pop`. Never pop onto the protected base.

## Phase 3: Merge strategy

If the user already named an **explicit** strategy, use it. A bare "merge", "merge the PR", or "merge it" is **not** a named strategy — AskQuestion.

| User said | `merge_method` | `gh` flag |
|-----------|----------------|-----------|
| squash / squash and merge | `squash` | `--squash` |
| merge commit / merge commits | `merge` | `--merge` |
| rebase / rebase and merge | `rebase` | `--rebase` |

Otherwise AskQuestion:

```
prompt: "Which merge strategy?"
options:
  - Squash and merge
  - Merge commit
  - Rebase and merge
```

---

## Phase 4: Merge

**Via MCP:**

```
CallMcpTool: server=github, toolName=merge_pull_request
arguments: { "owner": "<owner>", "repo": "<repo>", "pullNumber": <number>, "merge_method": "<squash|merge|rebase>" }
```

Then delete the remote head. GitHub MCP has no delete-branch tool:

```bash
gh api -X DELETE repos/<owner>/<repo>/git/refs/heads/<head>
```

If `gh` is unavailable: `git push origin --delete <head>`.

If the delete returns 404, the branch is already gone — continue.

**Via CLI:**

```bash
gh pr merge <number> --<squash|merge|rebase> --delete-branch
```

Do not continue to Phase 5 unless the merge succeeded.

---

## Phase 5: Local cleanup

Checkout target is always the PR base (`base.ref`). That is `main`, `staging`, a parent feature branch, or whatever the PR targeted.

```bash
git fetch --prune
```

If the local base does not exist:

```bash
git checkout -B <base> --track origin/<base>
```

Otherwise, if the current branch is the PR head (or any branch other than `<base>`):

```bash
git checkout <base>
```

Then:

```bash
git pull --ff-only
```

If a local branch named `<head>` still exists and it is not the current branch:

```bash
git branch -d <head>
```

If `-d` refuses (unmerged commits), AskQuestion:

```
prompt: "Local branch `<head>` has commits not in `<base>`. Force-delete it?"
options:
  - Yes, git branch -D
  - No, keep the local branch
```

---

## Phase 6: Summary

Display:

- PR URL and number
- Merge method
- Deleted remote head (yes / already gone / failed — see Error Recovery)
- Deleted local head (yes / kept / did not exist)
- Current branch (`git branch --show-current`) and `git log -1 --oneline`

---

## Error Recovery

**Auth missing or `get_me` / `gh auth status` fails:**
- AskQuestion with a single option: "I've authenticated — retry"
- Re-run the GitHub API Access checks. Repeat the gate if still failing.

**PR URL owner/repo differs from origin:**
- Stop in Phase 1.1. Do not fall back to origin or guess.

**No PR for the current branch:**
- List open PRs (Phase 1.1 step 4).

**Merge fails (required reviews, failing checks, 405/409):**
- Read the error. Do not retry with a different strategy. Tell the user what GitHub blocked and stop. (A `BLOCKED` status *before* merge is not this case — use the Phase 2 AskQuestion.)

**MCP merge succeeded but remote-branch delete failed:**
- Report the merge as done. Retry delete once with `git push origin --delete <head>`. If that fails, tell the user the remote head is still there and give the ref name. Continue Phase 5.

**`git checkout <base>` fails (dirty tree, unknown pathspec):**
- If dirty, return to the Phase 2 stash prompt.
- If the base ref is missing locally and on `origin`, stop — the PR base does not exist in this clone.

**`git pull --ff-only` fails:**
- Do not rebase or merge locally. Report that `<base>` has diverged locally and stop.

**`git branch -d` refused:**
- Follow the Phase 5 AskQuestion. Never run `-D` without that confirmation.
